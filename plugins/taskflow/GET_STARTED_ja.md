# taskflow を始めよう

プロジェクト作業を `pj:<project>` で始めると、Claude は答える前にそのプロジェクトの仕掛中の作業を把握します。taskflow はチャットをまたいで作業・決定・次の一手を保つため、増えていく Claude Code のセッションがあなたの ToDo リストになることはありません。

## こんなこと、ありませんか？

- 大きな作業を複数のチャットに分けたら、どのチャットに最新の進捗があるのか分からなくなった。
- 何かが仕掛中なのは分かるのに、何が残っているのかすぐには見えない。
- 決定したことや調査結果を覚えているのに、古いチャットの中に埋もれている。
- また説明し直すことになるので、新しいチャットを始めるのをためらう。

このために別の管理表を維持する必要はありません。いつも通り Claude と話せば、taskflow がプロジェクトの作業を整理します。

## 最初にすること

作業を始めるとき、プロンプトの先頭でプロジェクト名を指定します。

```
pj:customer-portal ログイン画面を刷新して
```

新しいチャットに戻るときも同じプロジェクト名を使います。同じチャット内では、`pj:` を繰り返す必要はありません。プロジェクト名を思い出せないときは、`pj:?` と入力してください。

## 仕掛中の作業から、次の一手まで

顧客ポータルを複数のチャットに分けて改善する場面を考えてみましょう。

1. 最初のチャットで `pj:customer-portal ログイン画面を刷新して` と入力します。Claude はプロジェクトの作業中タスクを把握してから、あなたと作業を進めます。
2. いつも通り Claude と作業します。作業が進むにつれ、タスクの進捗と残りの作業リストが最新に保たれます。チャットが終わると、そのセッションで行った作業がタスクに記録されます。
3. 後日の新しいチャットで、`pj:customer-portal /progress audit` と入力します。taskflow は全タスクを残作業で分類するため、まだ仕掛中の作業と完了にできそうな作業を確認できます。
4. 選んだチャットでタスクを続けます。Claude はプロジェクトと作業中タスクの状況を把握しているので、古いチャットから作業を組み立て直す必要はありません。
5. 本当に完了したら、`/progress approve login-screen` と伝えます。Claude は Done にする前にあなたの OK を求めます。

## 作業全体を一目で見る

`/kanban` を実行すると、すべてのプロジェクトとタスクをローカルのボードで確認できます。ステータス別またはプロジェクト別に表示し、絞り込みや、タスクに紐づくセッション履歴を開けます。

## 主導権はあなたにあります

- taskflow はプロジェクトを推測しません。プロジェクトを指定しておらず、このチャットですでに設定もされていなければ、静かに何もしません。
- タスクを Done にするには、必ずあなたの明示的な承認が必要です。
- プロジェクトの作成や notes の保存を頼んだときも、Claude は変更前に確認します。

## 今日から始める

taskflow は Claude Code で動作します。次の一度だけインストールします。

```
/plugin marketplace add gigamori/ai-agent-toolkit
/plugin install taskflow@ai-agent-toolkit
```

ほかに設定は不要です。workspace で初めて `pj:<project>` を使うと、taskflow がプロジェクト用の場所を作ります。詳しい使い方は [ユーザーガイド](USER_GUIDE_ja.md) を参照してください。
