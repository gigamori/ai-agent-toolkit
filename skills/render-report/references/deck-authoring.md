# Deck Authoring

デッキ著述役 **[A]** の手順。report.md を読み、[deck-md-contract.md](deck-md-contract.md) に準拠した deck-spec を 1 本書く。

## 立ち位置

report.md は内容の正本であり、**書き換えない**。deck-spec は媒体（スライド）向けに再著述した別の文書であり、短縮・再構成はすべてここで行う。

[A] は officecli に触れない。pptx を生成しない。スライドの座標も決めない（それは [deck-archetypes.md](deck-archetypes.md) と レンダリング役 [R] の仕事）。出力は deck-spec の markdown 1 本だけ。

## 入力

| 入力 | 内容 |
|------|------|
| report.md | 契約準拠のレポート正本（全文） |
| 本ファイル | 著述ルール |
| deck-md-contract.md | 出力の構造契約 |
| deck-archetypes.md | 容量目安（どこまで短くすべきかの判断材料） |
| 差し戻し所見 | 再入時のみ。G-A の違反行、G-B の逸脱所見、または G-R の overflow |

分析の中間生成物（ハンドオフ、統計出力、生データ）を読まない。report.md に書かれていないことは deck-spec に書けない。

## 忠実性ルール

1. **数値は原文転記**。桁区切りの表記も含めてそのまま写す。丸め・単位変換・「約」への言い換えを禁止する。`45,211` を `4.5万` にしない。
2. **n と分母を落とさない**。`evidence` に載せる数値は report.md と同じ n・分母の併記を保つ。分母が異なる指標を 1 文に並べない。
3. **確信度は原文一致**。`- 確信度:` の値（記号 + 訳語）をそのまま `confidence` に写す。括弧付きの但し書きも落とさない。
4. **様相を強めない**。「排除できない」を「排除された」に、「示唆する」を「示す」に、「参考値」を「結果」にしない。留保・限定・条件節を落とすことは、文を短くする手段として認められない。
5. **順序を変えない**。`findings` の優先順、発見事項の並びは report.md のとおり。強調の付け替え（弱い所見を先頭に出す等）を行わない。
6. **図表は宣言済みのものだけ**。チャートアノテーションは report.md にあるものを原文のまま写す。新しいチャートを作らない。source 表は全行全列そのまま写す。
7. **`purpose: findings` のレポートに行動動詞を足さない**。report.md 側で禁じた提案表現を、媒体を理由に復活させない。

## 生存規則

deck-spec は report.md の全文を運ばない。落としてよいものと、落としてはいけないものを次のとおり固定する。

### 必ず残す

- エグゼクティブサマリの**主要な発見**と**主な限界**
- 各 `F-n` の見出しの主張、`確信度`、`解釈` または `実務示唆`、`限界`
- `限界と注意事項` のうち**標本独立性の違反開示**（該当する記述が report.md にある場合）

### 統合してよい

- `限界と注意事項` のその他の項目。複数項目を 1 文に束ねてよい。ただし**項目の消失は許されない** — 束ねた文にその項目の主張が残っていること。
- `検証状態` の詳細。本文スライドに載せず落としてよい（G-B は照合しない）。
- `根拠` の頑健性チェックの列挙。代表的な数値と結論を残せば、変種の列挙は落としてよい。
- `付録` の中身。`appendix` スライドは trace だけでよい。

### 落としてよい

- 節の導入文・接続表現
- 同じ数値の再掲
- report.md 内の相互参照（「付録参照」等）

## 原型ごとに書くこと

| 原型 | 何枚 | 中身 |
|------|------|------|
| `title` | 1 | frontmatter のみ。スロットなし |
| `exec-summary` | 1-2 | `message`（目的と位置づけ）、`findings`（主要な発見、報告と同じ優先順）、`limits`（主な限界） |
| `section` | 各節 1-2 | `分析対象データ` / `データの基本的特徴` / `限界と注意事項`。`headline` は 1 文の主張、`body` は圧縮した本文 |
| `finding` | 各 `F-n` に 1 | `headline`（見出しの再著述、`[F-n]` は除去）、`confidence`、`body`（解釈の圧縮）、`evidence`（根拠の数値）、`limit`（report.md に `- 限界:` があるとき必須） |
| `evidence` | チャートを持つ `F-n` に 1 | チャートアノテーション + source 表。スロットは任意 |
| `appendix` | 付録の小見出しごとに 1 | `trace` のみ |

`finding` を 2 枚に割ってよい（同じ trace を 2 枚が持つ）。ただし `confidence` はどちらか一方に必ず載せる。

## 分量

[deck-archetypes.md](deck-archetypes.md) の「容量目安」に収まるよう書く。目安であって保証ではないので、超えた分は G-R の overflow として戻ってくる。戻ってきたら**該当スライドだけ**を短くし、report.md には触れない。

短縮の順序（上から順に削る）:

1. 節の導入文・接続表現
2. 頑健性チェックの変種列挙
3. 例示の一部（列挙を代表 2 例に絞る)
4. スライドを 2 枚に割る

**留保・分母・n・確信度は短縮の対象にしない**。ここまで削って収まらない場合、スライドを割る。

## 出力

deck-spec の markdown を 1 ファイル書き、パスを返す。書いたあとの検証（G-A / G-B）は [A] の仕事ではない。

再入（差し戻し）時は、受け取った所見が指すスライドのみを直す。所見に無いスライドを「ついでに」直さない — 直した箇所は G-B の再判定を受けるため、無関係な変更は再判定の対象を無駄に広げる。
