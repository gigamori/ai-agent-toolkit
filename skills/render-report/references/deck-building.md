# Deck Building

デッキ役 **[D]** の手順。report.md を読み、pptx を 1 本作る。

## 読むもの

| # | ファイル | 何のために |
|---|---------|-----------|
| 1 | **`~/.claude/skills/officecli-pptx/SKILL.md`** | **最初に、全文を読む。この成果物の標準である** |
| 2 | report.md | 内容の正本（全文） |
| 3 | 本ファイル | 忠実性の制約と、封じ込めの手順 |

1 を読まずに描き始めない。1 が無ければ `officecli help pptx` で代替し、代替したことを申告する。

分析の中間生成物（ハンドオフ、統計出力、生データ）を読まない。

## 入力

| 入力 | 内容 |
|------|------|
| report.md のパス | 契約準拠のレポート正本 |
| 出力パス | 生成する pptx |
| 範囲 | 任意。「F-6 と F-7 のみ」「主要な発見のみ」のように、デッキに載せる部分の指定。指定があればその部分だけから作る |
| 差し戻し所見 | 再入時のみ。G-1 の違反行、[J] の所見、または [H] の指摘 |

## あなたの仕事

デッキ全体を作る。枚数・構成・視覚手段・テーマ・何を落とすかはあなたが決める。その判断がこの役の中身である。読み手は分析を実行していないビジネス読者。

report.md は書き換えない。媒体向けに再著述するのはデッキ側であり、正本ではない。

## 内容について、守ること

- レポートは観察研究である。発見には確信度（◎ ○ △ ×）と限界が明示され、いくつかの発見は「特定できない」「棄却」として書かれている。それらを肯定的な結果として見せるデッキは、レポートを誤って伝える。数値には分母と n が付いている。読み手が「何に対する率か」を判別できない率を置かない。
- レポートに無い数値を作らない。

これ以外は、あなたがデッキの著者である。媒体に合わせて書き直してよい。

## 品質ゲート

officecli-pptx の Delivery Gate を全部通す — Gate 1（validate）、Gate 2（view issues）、Gate 2b（placeholder 走査）、Gate 3（全スライドを screenshot し、チェックリストに対して adversarial に判定、fix-verify 最大 3 巡）、そして `officecli save`。

**Gate 3 の判定は自分でしない。** fresh subagent に screenshot とチェックリストを渡して判定させる（officecli-pptx 自身がそう勧めている — 作った本人は "looks fine" に偏る）。監査役の画像も所見もこの役の中に閉じ、呼び出し元へ返さない。

返す前に、文言の出所を機械で検める。

```bash
uv run --script <skill>/scripts/check_pptx_text.py <pptx> <report.md> [--scope F-6,F-7]
```

判定されるのは 2 点（範囲内の各 `F-n` が面にある、`F-n` と確信度記号が同じスライドにある）。違反が出たら直す。

加えて「report.md に無い数値」が列挙される。これは判定ではない — 区切りの `01` のような装飾番号もここに並ぶ。読むべきは、列挙の中に**データ値**（率・件数・差・比）が混じっていないか。混じっていれば、それはレポートに無い数値なので消す。図として必要でも描けない。監査役は PNG しか見ないので、この列挙だけがそれを見る。

## 封じ込め

screenshot の確認と修正はこの役のコンテキスト内で完結させる。呼び出し元へ画像を返さない。呼び出し元のコンテキストを画像で埋めないための分離であり、手を抜く理由ではない。

## 申告する

最終応答に次を含める。**画像は返さない。**

```
pptx: <パス>
contact sheet: <パス>
枚数: <N>
構成: <1 段落>
Gate 1 / 2 / 2b / 3: <結果。Gate 3 は監査役の巡数と最終判定>
check_pptx_text.py: <結果>
未収束の項目: <スライドと問題。無ければ「なし」>
officecli-pptx SKILL.md: <読んだ / 不在のため officecli help で代替>
```
