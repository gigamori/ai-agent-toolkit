# Report Markdown Contract

分析レポート markdown 正本の構造契約。render-report が pptx / docx / xlsx へ機械変換できる形を定義する。

この契約はパイプライン非依存。特定の分析スキルの工程名・内部用語を含めない。任意の定量分析パイプライン（クロス集計、統計検定、モデリング等）が本契約に準拠した markdown を生成すれば、render-report で変換できる。

決定論チェック: `scripts/validate_contract.py`

## Frontmatter（必須）

```yaml
---
title: "レポートタイトル"
purpose: "findings"
---
```

| キー | 必須 | 値 |
|------|------|-----|
| `title` | 必須 | レポートタイトル。変換後の表題に使う |
| `purpose` | 必須 | `findings`（ニュートラル報告）または `action`（推奨アクション付き） |
| `data_source` | 任意 | 主データの識別子。付録の再現性情報に転記される |

値はすべてダブルクオートで囲む。

## セクション構成（順序固定）

```
# タイトル
## エグゼクティブサマリ
## 分析対象データ
## データの基本的特徴
## 発見事項
## 限界と注意事項
## 付録
```

全セクションが必須。順序を変えない。セクション名を変えない。

### エグゼクティブサマリ

- 分析目的（1-2文）
- 主要な発見（3点以内、優先順）
- 推奨アクション（`purpose: action` のときのみ。`findings` では置かない）
- 主な限界（1-2点）

### 分析対象データ

データソース、対象期間、対象範囲、1行が表すもの、除外条件。

### データの基本的特徴

分布・欠損・外れ値など、発見事項の前提となる記述。

### 発見事項

クレームブロックの並び。1ブロック = 1つの発見。優先順に並べる。

### 限界と注意事項

データの制約、手法の限界、解釈上の注意、追加分析の必要性。

### 付録

以下の小見出しを持つ。

```
### 再現性
### 変数対応表
### 検証詳細
```

`### 再現性`: データファイル、対象期間、フィルタ条件、実行環境（エンジン起動コマンド等）、実施した検証の一覧。
`### 変数対応表`: 生カラム名とレポート本文で使うビジネス名の対応表（GFM テーブル）。
`### 検証詳細`: 本文に載せない検定・診断の詳細。

## クレームブロック

`## 発見事項` 配下の `###` 見出し 1つが 1クレームブロック。変換時の最小単位（pptx では 1-2 枚のスライドになる）。

```markdown
### [F-1] Google 流入の転換率は他チャネル比 1.8 倍（n=1,240）

- 根拠: 転換率 12.4%（n=1,240、分母=Google 流入ユーザー）vs 全体 6.9%（n=8,530、分母=全ユーザー）。絶対差 5.5 ポイント、相対差 1.8 倍
- 検証状態: カイ二乗独立性検定 p<0.001、Bonferroni 補正後も有意。デバイス層別後も各層で方向が一致
- 確信度: ○ 小規模試行を推奨できる強さ
- 解釈: 流入チャネルと転換率の関連は層別後も残存する。ただし観測データであり、チャネル選択の自己選択バイアスは統制していない
- 限界: 期間が 30 日のため季節性は評価していない
```

### 必須要素

| 要素 | 形式 | 規則 |
|------|------|------|
| 見出し | `### [F-n] メッセージ` | `n` は 1 から連番。メッセージはアサーション（主張1文）。疑問形・体言止めの主題ラベルは不可 |
| `- 根拠:` | 数値 | すべての数値に n と分母を併記する。分母が異なる指標を同一文で比較しない |
| `- 検証状態:` | 文 | 実施した検証と、補正・調整後の判定。未検証なら「未検証」と書く |
| `- 確信度:` | 記号 + 訳語 | `◎` / `○` / `△` / `×` のいずれかで始める |
| `- 解釈:` または `- 実務示唆:` | 文 | `purpose: findings` では `解釈`、`action` では `実務示唆`。混在させない |

### 任意要素

| 要素 | 規則 |
|------|------|
| `- 限界:` | このクレーム固有の限界 |
| テーブル | GFM テーブル。チャート化するテーブルには直前行にチャートアノテーションを置く |

### 確信度の記号

| 記号 | 意味 |
|------|------|
| `◎` | 介入実験または統制後も残存。施策判断に使える |
| `○` | 層別・統制後も関連が残存。小規模試行を推奨できる強さ |
| `△` | 時系列先行など部分的根拠のみ。追加検証が先 |
| `×` | 関連の観察のみで根拠なし。参考情報 |

記号の後にビジネス向けの訳語を続ける。

## チャートアノテーション

チャートは、アノテーションを付けた GFM テーブルからのみ生成される。本文に実体のないグラフ参照を書いてはならない。

```markdown
<!-- chart: bar x=channel y=cvr title="チャネル別転換率" -->

| channel | cvr |
|---------|-----|
| google  | 12.4 |
| direct  | 6.1 |
```

| パラメータ | 必須 | 値 |
|-----------|------|-----|
| 種別 | 必須 | `bar` / `line` / `pie` のいずれか。`chart:` 直後に置く |
| `x=` | 必須 | カテゴリ軸に使う列名。テーブルのヘッダに実在すること |
| `y=` | 必須 | 値に使う列名。テーブルのヘッダに実在すること。カンマ区切りで複数可 |
| `title=` | 任意 | チャートタイトル。ダブルクオートで囲む |

規則:

- アノテーションの次の非空行から GFM テーブルが始まること
- `x=` / `y=` の列名はそのテーブルのヘッダに存在すること
- アノテーションのないテーブルはチャート化されず、表として変換される

## 禁止事項

| 禁止 | 理由 |
|------|------|
| 実体のないグラフ・図の参照（「下図参照」等） | 本契約では宣言されたアノテーションからのみ図が生成される |
| 分母の異なる指標の同一文比較 | 母集団取り違えの典型的な事故経路 |
| n・分母のない数値 | 根拠として検証できない |
| `purpose: findings` での推奨アクション・行動動詞 | ニュートラル報告の位置づけを壊す |
| 生カラム名の本文使用 | 読み手が解釈できない。変数対応表で対応付けたビジネス名を使う |

`purpose: findings` でも「追加分析の提案」は許可される（限界と注意事項セクションに置く）。禁止されるのはビジネス行動の提案のみ。
